Task 4: MP4Muxer Integration into H264Recorder
================================================
Date: 2026-04-30

CHANGES MADE:
-------------
1. internal/recorder/h264.go:
   - Added muxer *muxer.MP4Muxer and trackID int fields to H264Recorder
   - Removed curTempPath (no longer needed - muxer writes directly to finalPath)
   - Added lastFrameTime time.Time for duration calculation
   - Modified writeFrames(): 
     * Only processes video NAL units (type 5=IDR, type 1=P-frame)
     * Skips SPS/PPS from WriteSample (they go to AddH264Track)
     * Creates MP4Muxer with finalPath on first video frame
     * Strips 4-byte Annex B start code (data[4:]) before passing to WriteSample
     * Calculates PTS (time since segment start) and duration (time since last frame)
   - Modified closeCurrentSegment():
     * Calls muxer.Close() to finalize MP4 file
     * No longer calls store.WriteFrame or store.CloseSegment
   - Added import: "github.com/Mi-Bee-Studio/MiBeeNvr/internal/muxer"

ARCHITECTURE:
-------------
Before: writeFrames() -> store.WriteFrame(tempPath, rawNAL) -> raw bytes -> .tmp -> rename .mp4
After:  writeFrames() -> muxer.WriteSample(trackID, nalu, pts, dur) -> muxer.Close() -> valid MP4

Key decisions:
- Write directly to finalPath (not tempPath) since MP4Muxer writes entire file on Close()
- SPS/PPS passed to AddH264Track, not written as samples
- Only IDR (type 5) and P-frame (type 1) NAL units written as samples
- Duration defaults to 33ms (30fps) when time delta is zero
- SegmentStore interface kept unchanged (WriteFrame/CloseSegment still exist but unused for H264)
